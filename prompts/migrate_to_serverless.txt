## Important: Staging Copy Workflow

Do NOT modify the original deployed notebooks. Follow this workflow:

1. Copy each notebook to a staging folder: `/Workspace/Migration/staging/<job_name>/`
2. Apply all changes ONLY to the staging copies
3. The staging copies will have hardcoded environment values (e.g., `uat_catalog`) — this is expected for testing
4. The developer will later apply the change manifest to the repo source files (which have %placeholder% tokens)
5. Never export staging copies back to the repo

```python

Preserve the folder structure in the staging area.

## Step 2: Apply ANSI-Safe Fixes (Path A, B, C)

Apply every ANSI fix from the change manifest. For each finding:

1. Navigate to the specified cell/line
2. Apply the exact replacement from the manifest
3. Verify the fix is syntactically correct

Key patterns:
- `CAST(x AS INT)` → `TRY_CAST(x AS INT)`
- `col / divisor` → `TRY_DIVIDE(col, divisor)` or null guard
- `boolean_col = 1` → `boolean_col IS TRUE`
- `to_date(col, fmt)` → `try_to_date(col, fmt)`
- `to_timestamp(col, fmt)` → `try_to_timestamp(col, fmt)`
- `array[i]` → `TRY_ELEMENT_AT(array, i+1)` or bounds check
- `map['key']` → `TRY_ELEMENT_AT(map, 'key')`

**Do NOT set spark.sql.ansi.enabled = false.** Fix the code instead.

Reference: resources/07-ansi-compliance-reference.md

## Step 3: Remove Unsupported Operations (Path B, C)

- Remove `.persist()` / `.cache()` / `.unpersist()`
- Remove `CACHE TABLE` / `UNCACHE TABLE`
- Remove `REFRESH TABLE`
- Remove `MSCK REPAIR TABLE`
- Convert `CREATE MATERIALIZED VIEW` → note for SQL Warehouse task
- Convert global temp views → session-scoped temp views

Reference: resources/14-serverless-blockers.md

## Step 4: Migrate Spark Configs (Path B, C)

For each `spark.conf.set()` call:
- If unsupported on serverless → remove (add comment noting removal)

- Remove `spark.sql.ansi.enabled = false` — fix code instead

Reference: resources/05-spark-config-classic-to-serverless.md

## Step 5: Migrate Environment Variables (Path B, C)

Replace every `os.environ.get()` with `dbutils.widgets.get()`:

```

These values come from the job-level parameters block in the job JSON.
